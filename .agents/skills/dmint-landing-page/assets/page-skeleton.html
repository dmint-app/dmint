AI can request.
Dmint decides.

An open-source gate between AI agents and the tools they call. Every request is checked against a policy you control — before anything runs, with no LLM in that decision.

the problem

Agents already have write access. Most of them have no gate at all.

An agent with tool access can call anything it decides to — delete a record, push to production, move money — the moment it decides to. Without an enforcement layer in between, "the model shouldn't do that" is a hope, not a guarantee.

how it works

Every request ends in exactly one of three outcomes.

Dmint evaluates the request against your policy — deterministically, no model involved in the decision itself. One of three things happens next.

01

Request is bound exactly

The tool, arguments, and context are canonicalized and hashed — if anything changes later, even one character, the hash won't match.

02

Policy decides, not a model

Evaluation is deterministic pattern matching against policy.json — sub-millisecond, no network call, nothing for a prompt injection to influence.

03

Approval is cryptographically bound

A human approval is an Ed25519 signature over that exact request hash — reused, replayed, or altered requests fail verification.

the permission model

A capability is three things, not a role.

Dmint doesn't grant "database access" or "admin." Every rule names a tool, an action, and a resource — postgres.select on public.users is a capability. Anything that exact combination doesn't cover is denied by default, same as everything else in policy.json.

deterministic by design

The model proposes. It never decides.

A model asked to judge its own tool call is still a probabilistic check — and a prompt injection only has to beat it once. Dmint's decision runs in compiled code against policy.json, with no model call anywhere in the authorization path.

protecting MCP servers

One gateway in front of every downstream server.

dmint-mcp sits between an agent and its MCP servers — Postgres, the filesystem, GitHub, anything else it's wired to. It aggregates their tools, validates remote endpoints before trusting them, and checks every call against policy before it reaches a real server.

storage

SQLite by default. PostgreSQL if you need it.

Switching backends is one environment variable, DMINT_DATABASE_URL. Whichever you choose, only Dmint Core reads or writes it directly — the CLI, dashboard, and gateway all go through Core's API, never raw SQL.

notifications

A Slack ping, never a security dependency.

When a request needs a human, Dmint can notify Slack, Discord, or Teams with the exact command to approve it. If the webhook times out or fails, the authorization decision doesn't change — the agent stays paused either way.

a real request

What this looks like for one call.

$ agent: delete_customer(id="c_8213")

dmint: checking policy for delete_customer...
dmint: destructive action on prod — approval required
dmint: notified #approvals on slack
dmint: waiting for signed approval (apr_9f2a...)

$ dmint pending
apr_9f2a   delete_customer   public.customers   waiting 00:14

$ dmint approve apr_9f2a --reason "confirmed with support ticket #4021"
dmint: signature verified, request matches exactly
dmint: executing delete_customer(id="c_8213")
reference

The CLI you'll actually run.

Everything above is also a command — policies, approvals, and the gateway, all from one binary.

dmint create-policy

Wizard that turns plain-language requirements into a verified policy.json.

dmint create-mcp-policy

Discovers an MCP server's tools and generates its policy and gateway config together.

dmint verify-policy

Validates policy.json offline — zero network calls, zero model calls.

dmint pending

Lists every request currently waiting on a human decision.

dmint approve / reject

Signs or rejects a pending request straight from a terminal.

dmint dashboard

A local web UI for the same queue, polling every 5 seconds.

install

One package, local by default.

SQLite and local policy files out of the box — nothing to stand up before you can try it.

pip install dmint
dmint create-policy

# optional — SQLite is used otherwise
export DMINT_DATABASE_URL=postgresql://localhost/dmint

policy.json

{
  "rules": [
    { "tool": "read_records",
      "effect": "allow" },

    { "tool": "delete_customer",
      "effect": "approval_required" },

    { "tool": "drop_table",
      "effect": "deny" }
  ]
}
