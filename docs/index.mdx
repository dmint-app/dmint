# Deterministic Security for AI Agent Tool Calls

Dmint places an unbypassable, code-governed authorization boundary between AI agents and privileged execution environments.

---

## The Problem

Autonomous agents (Cursor, Claude Code, Antigravity, LangChain pipelines) frequently possess high-privilege access to execute commands, query databases, read files, and call external APIs.

Prompt-based guardrails ("Please do not run `DELETE` without asking") fail when an agent encounters prompt injection, jailbreaks, or hallucinations:

```text
Without Dmint (Probabilistic & Vulnerable):
AI Model ────[ System Prompt / Model Guardrail ]────► Executes DROP TABLE / RM -RF

With Dmint (Deterministic & Fail-Closed):
AI Model ────► Tool Call ────► [ Dmint Policy Engine ] ────► ALLOW: Executes tool
                                      │
                                      ├─► DENY: Fails closed immediately
                                      └─► APPROVAL_REQUIRED: Halts until signed human approval
```

Dmint evaluates every tool request against deterministic, declarative policies before the protected capability runs. There is **zero LLM evaluation** in the runtime authorization decision path.

---

## 10-Line Example

Protect a sensitive tool with policy evaluation and human approval:

```python
from dmint import Dmint, Policy, Rule, TrustedContext

# 1. Define deterministic rules
policy = Policy([
    Rule.allow("database", "query"),
    Rule.approval_required("database", "delete"),
])

# 2. Initialize the engine
engine = Dmint(
    policy=policy,
    agent_id="agent-prod-01",
    context=TrustedContext({"environment": "production"}),
)

# 3. Guard the callable
@engine.protect("database.delete")
def delete_records(table: str, condition: str) -> int:
    return 42

# 4. Tool execution halts and persists a pending approval record
try:
    delete_records("users", "inactive = true")
except Exception as exc:
    print(f"Intercepted: {exc.code} (Request ID: {exc.request_id})")
```

Output:
```text
Intercepted: DMT_APPROVAL_REQUIRED (Request ID: req_9k2L...m4P1)
```

The tool was never called. To proceed, an authorized human signs an Ed25519 assertion via the local dashboard or CLI (`dmint approve`), and the host application retries.

## How It Works

```text
   AI Agent Call
         │
         ▼
 1. Parameter Canonicalization (RFC 8785 JSON Canonicalization Scheme)
         │
         ▼
 2. SHA-256 Request Fingerprinting (b"dmint/request-fingerprint/v2\x00")
         │
         ▼
 3. Deterministic Policy Evaluation (Deny-overrides, default-deny)
         │
 ┌───────┴────────────────────────┐
 │                                │
 ▼                                ▼
ALLOW                     APPROVAL_REQUIRED
 │                                │
Executes Callable          Halts execution; persists record in SQLite/Postgres;
                           emits webhook notification (Slack/Discord/Teams)
                                  │
                                  ▼
                           Human Review (Dashboard or CLI)
                                  │
                                  ▼
                           Host Retries with Ed25519 Signed Token
                                  │
                                  ▼
                           Atomic Single-Use Consumption & Execution
```

## Who It Is For

- **AI application engineers** deploying agents with access to production databases, cloud APIs, or file systems.
- **Enterprise teams** using Model Context Protocol (MCP) in Cursor, Claude Code, or Antigravity who require an audit trail and human-in-the-loop review for destructive actions.
- **Security auditors** needing deterministic proof that an agent cannot exceed policy rules regardless of prompt manipulation.

### Who Should Not Use It

- If you want an LLM to judge whether text "looks suspicious" or perform content moderation, use an LLM input guardrail. Dmint evaluates strict mathematical rules against exact arguments and context.
- If your agent runs as the same unisolated OS user as your application and has direct shell access, an in-process library cannot protect local files or signing keys. You need container or OS-level user isolation.

## Project Status

- **Version**: `2.0.1`
- **Supported Python**: `3.10`, `3.11`, `3.12`, `3.13`
- **Supported Transports**: Python decorator (`@engine.protect`), MCP Stdio proxy, MCP Streamable HTTP proxy.
- **Backends**: SQLite (default, with WAL mode and row HMAC integrity) or PostgreSQL via SQLAlchemy (`DMINT_DATABASE_URL`).
- **Cryptographic Standard**: RFC 8785 (JCS) canonicalization, SHA-256 domain-separated hashing, Ed25519 public-key approval signatures.
