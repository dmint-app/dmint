# Human Approvals with `dmint dashboard`

The Dmint Dashboard is a lightweight, local web interface that gives human operators real-time oversight over AI agent actions.

When an AI agent attempts an action that requires approval, the request is intercepted and displayed in the dashboard for human inspection.

```text
┌─────────────────┐
│    AI Agent     │  (Paused awaiting approval)
└────────┬────────┘
         │
         ▼
┌─────────────────┐     5-second short polling     ┌─────────────────┐
│ Core-Owned DB   │ ◄──────────────────────────── │ dmint dashboard │
│ (approvals.db)  │                                │ (Web Browser)   │
└─────────────────┘                                └────────┬────────┘
                                                            │
                                                   Human clicks [Approve]
                                                            │
                                                            ▼
                                                   Signed Ed25519 Assertion
```

## Launching the Dashboard

You can start the dashboard directly using the `dmint` CLI:

```bash
# Basic startup with SQLite:
dmint dashboard --db-path ./approvals.sqlite3

# Or with PostgreSQL (via flag or DMINT_DATABASE_URL):
dmint dashboard --database-url postgresql://user:pass@localhost:5432/dmint

# Or with matching deployment epoch:
dmint dashboard --db-path ./approvals.sqlite3 --deployment-epoch prod-v1 --port 8080
```

By default, the server binds to **`http://127.0.0.1:8080`**.

<Warning>
**Deployment Epoch Isolation**:
Dmint enforces strict cryptographic deployment epoch boundaries to isolate environments and prevent replay attacks.
If your agent initialized `SQLiteApprovalStore("./approvals.sqlite3", deployment_epoch="prod-v1")`, you **must** supply `--deployment-epoch prod-v1` when starting the dashboard. If the epochs do not match, pending records will be hidden to prevent unauthorized cross-epoch approvals.
</Warning>

### Configuration Options

| Option | Environment Variable | Default | Description |
|---|---|---|---|
| `--db-path` | `DMINT_DB_PATH` | None | Path to Core-owned SQLite database (required if `--database-url` is not provided) |
| `--database-url` | `DMINT_DATABASE_URL` | None | Database connection URL (`postgresql://...` or `sqlite:///...`). Takes precedence over `--db-path` |
| `--host` | `DMINT_DASHBOARD_HOST` | `127.0.0.1` | Local bind host |
| `--port` | `DMINT_DASHBOARD_PORT` | `8080` | Local bind port |
| `--deployment-epoch` | `DMINT_DEPLOYMENT_EPOCH` | `default` | Deployment epoch matching running Core (`prod-v1`, `staging`, etc.) |
| `--authority-issuer` | `DMINT_AUTHORITY_ISSUER` | `dmint-dashboard` | Issuer ID for the local authority |
| `--approver-id` | `DMINT_APPROVER_ID` | `dashboard-human` | Approver ID stamped on records |

## Dashboard Features

### 1. 5-Second Real-Time Polling
The dashboard automatically queries `/api/dashboard` every 5 seconds. When your agent pauses on a sensitive tool call, the card appears on your screen without requiring a browser reload.

### 2. Deep Argument Inspection
Click any pending request to view:
- The target capability: `tool.action`
- The target resource
- The exact JSON arguments payload
- The cryptographic SHA-256 request fingerprint
- The requesting agent identifier

### 3. One-Click Approval & Rejection
- **Approve**: Dmint's `LocalApprovalAuthority` generates an Ed25519 cryptographic signature over the request fingerprint and updates the record state to `APPROVED`.
- **Reject**: Marks the request as `REJECTED`. The agent's retry attempt will fail closed immediately.

### 4. Audit Log
The **Audit** tab maintains an immutable chronological record of all previously approved, rejected, and consumed actions.

## Architecture & Security Rules

<Warning>
**No Authentication (Local / Demo Use Only)**: The dashboard has no user login or authentication layer. It is designed to run locally on `127.0.0.1`. Do not expose port 8080 to the public internet without an authenticating reverse proxy (such as Cloudflare Access or Tailscale).
</Warning>

### Core Invariants Enforced by Dashboard:
- **Zero Direct SQL**: The dashboard package contains zero SQL queries and never connects directly to database drivers. It accesses approval data exclusively through Core's public methods (`list_pending()`, `approve_pending()`, `reject_pending()`).
- **Single Database Ownership**: Core is the sole owner of the database schema (SQLite or PostgreSQL). The dashboard never creates its own database tables.
- **Thread-Safe Storage**: Uses `ThreadSafeApprovalStore` with isolated thread-local SQLite connections or pooled PostgreSQL connections to guarantee safe concurrent access under Uvicorn worker threads.

## Terminal Approval Management (CLI)

If you prefer managing approvals entirely from the terminal or in headless CI/CD environments without running the dashboard web UI:

```bash
# 1. View all pending requests:
dmint pending

# 2. Approve a request with an audit note:
dmint approve apr_abc123... --reason "Authorized by security team"

# 3. Reject a request:
dmint reject apr_abc123... --reason "Disallowed per policy"
```

All terminal approval commands enforce the identical security guarantees:
- **Exact-Request Binding**: Approvals are bound byte-for-byte to the RFC 8785 canonical hash.
- **Policy Re-Verification**: `dmint approve` verifies the request against the current policy before signing. If the policy changed and now denies the request, approval is refused. Policy resolution follows strict precedence: `--policy <path>` $\to$ database authoritative policy (`store_policy` table) $\to$ local `./policy.json`. When using PostgreSQL, pass `--policy ./policy.json` explicitly if you want to override a cached database policy with local edits.
- **Single-Use Consumption**: Once consumed by the agent, replaying the assertion fails closed immediately.
